Week 6: Arrays Notes

Prelude & Motivation

Managing multiple data records using individual scalar variables quickly becomes unmaintainable as data scales.

Inefficient Scalar Variable Approach 
# Scaling manually with single variables is painful and inefficient
name1 = "Alice"
name2 = "Bob"
name3 = "Charlie"
name4 = "Dave"
name5 = "Eric"
# Imagine tracking 20+ records this way: name1... name20...

Arrays solve this limitation by providing a cohesive continuous structure capable of housing large quantities of related data under a single identifier.

Array Fundamentals

Arrays are organized data structures designed to store collections of homogeneous (similar) data types.

  • List of strings (e.g., student names)
  • List of numbers (e.g., age values, account balances)
  • List of calendar months

Declaration & Initialization

Array creation requires defining the array identifier and explicitly allocating the target capacity size.

RAPTOR Pseudocode Syntax 
SET array_name[size] = ""   # Initialize array for storing strings
SET array_name[size] = 0    # Initialize array for storing numeric values

# Practical Examples:
SET names[5] = ""           # Allocates space for 5 name records
SET ages[20] = 0            # Allocates space for 20 age values

Indexes & Data Access

An Index specifies an element's physical location within the structure.

Raptor Indexing Convention
In RAPTOR, array indexing is 1-based (starts at index 1 and steps up by 1).
names[] "Alice" "Bob" "Charlie" "Dave" "Eric"
Index 1 2 3 4 5
Access Examples 
PRINT names[4]   # Outputs "Dave"
PRINT names[1]   # Outputs "Alice"

# Variable-based indexing:
SET i = 3
PRINT names[i]   # Outputs "Charlie"
Invalid Access Operations

• PRINT names[6] — Runtime error: Access out of current initialized bounds.

• PRINT names[0] / names[-1] — Invalid index boundary.

• PRINT names — Syntax error: Array identifier requires an index reference.

• PRINT total[4] — Error: Indexing cannot be used on non-array variables.

Setting & Modifying Values

Assigning a new value to an indexed array element updates that specific slot independently.

Value Overwrite Operations 
# Overwriting index 5
SET names[5] = "Emma"
PRINT names[5]   # Outputs "Emma" (Replaces "Eric")

# Copying values between indexes
SET names[2] = names[1]  # Evaluates right side first: copies "Alice" to slot 2

# Re-assigning index 1
SET names[1] = "Bob"    # Slot 1 becomes "Bob". Slot 2 remains "Alice" (values are decoupled copies)

Edge Cases & Behaviors

RAPTOR exhibits distinct behavior rules regarding index access versus setting out-of-bound slots.

Out-Of-Bounds Assignment Rules 
SET names[6] = "Fabio"  # ALLOWED: Dynamically expands array allocation
PRINT names[6]         # ALLOWED: Prints "Fabio"
PRINT names[7]         # ERROR: Accessing uninitialized index 7

SET names[7] = ""      # ALLOWED: Blank string counts as an initialized value
PRINT names[7]         # ALLOWED: Outputs blank string
PRINT names[8]         # ERROR: Unassigned nonexistence

Counter-Loops Integration

Combining counter-loops with index counters (conventionally named i) allows rapid sequential iteration across entire arrays.

Complete Pattern: Forward & Reverse Iteration 
# Prompt user for entry capacity
PRINT "How many people are there?"
INPUT num_of_people

# Instantiate dynamic array size based on input
SET names[num_of_people] = ""

# 1. Forward Loop: Populate array
SET i = 1
WHILE i <= num_of_people:
    PRINT "Enter name #" + i
    INPUT names[i]
    PRINT names[i]
    SET i = i + 1

# 2. Reverse Loop: Print elements in reverse order
SET i = num_of_people
WHILE i >= 1:
    PRINT names[i]
    SET i = i - 1

Parallel Arrays

Parallel arrays consist of two or more synchronized arrays that share matching sizes and use identical index access keys to model multi-attribute entities.

Parallel Array Allocations 
SET names[5] = ""
SET ages[5] = 0
names[] "Alice" "Bob" "Charlie" "Dave" "Emma"
ages[] 27 24 25 28 22
Index Key 1 2 3 4 5
Synchronized Access Example 
SET i = 2
PRINT names[i]
PRINT ages[i]
# Output: Bob 24
