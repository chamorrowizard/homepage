The Lesson: Before writing actual executable code, software architects plan using Pseudocode. Order, blueprinting, and deliberate structure ensure that what we build stands firm without structural defects or logic bugs.

1. Program Architecture: Input, Processing, Output

Every program breaks down into three sequential steps.

1. Input

Gathering data from the user or external systems using keywords like INPUT.

2. Processing

Manipulating and storing variables through logic or math using SET.

3. Output

Displaying calculated or formatted information back to the user via PRINT.

2. Keywords Syntax Quick Guide

Standardized vocabulary for constructing algorithmic blueprints.

Keyword Syntax Pattern Purpose
PRINT PRINT <value> Displays text, calculated numbers, or prompts to the output console.
INPUT INPUT <variable> Pauses execution and reads user data into a specific memory container.
SET SET <variable> = <value> Assigns or overwrites the contents stored inside a single variable.

Value Types

  • String: Contained in double quotes "John". Literal character strings used for sentences or labels.
  • Number: Written without quotes 13.45 or 55. Can include integer or floating-point decimals.
  • Variable: Named container holding one value at a time. Evaluating a variable retrieves its underlying data value.

Variable Naming Directives

Hard Rules (Engine Enforced):

  • Cannot begin with a number (e.g. 4square)
  • Cannot contain spaces (e.g. first name)

Best Practices (Soft Rules):

  • Use snake_case for multi-word variables (first_name)
  • Use meaningful, descriptive terms; avoid ambiguous single-letters

4. Calculations, Order of Operations & Modulus

PEMDAS Order

P :: ( Parentheses )
E :: ^ Exponents
MD :: * / % (Mult, Div, Mod)
AS :: + - (Add, Sub)

Modulus Operator (%)

The Modulus operator % divides two numbers and returns the remainder.

5 % 2 = 1 (5 / 2 = 2 Remainder 1)

14 % 3 = 2 (14 / 3 = 4 Remainder 2)

3 % 14 = 3 (If left is smaller, result is left)
