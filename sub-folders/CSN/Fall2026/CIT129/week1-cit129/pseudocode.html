The Lesson: Before writing actual executable code, software architects plan using Pseudocode. Order, blueprinting, and deliberate structure ensure that what we build stands firm without structural defects or logic bugs.

1. Program Architecture: Input, Processing, Output

Every program breaks down into three sequential steps.

1. Input

Gathering data from the user using keywords like INPUT.

2. Processing

Manipulating, calculating, or storing data using SET.

3. Output

Displaying calculated or formatted information back using PRINT.

2. Keywords Syntax Quick Guide

Standardized vocabulary for constructing algorithmic blueprints.

Keyword Syntax Pattern Purpose
PRINT PRINT <value> Displays text, calculated numbers, or prompts to the output console. Strips outer quotes from strings.
INPUT INPUT <variable> Pauses execution and reads user input directly into a variable memory box.
SET SET <variable> = <value> Assigns or overwrites the contents stored inside a single variable container.

Value Types

  • String: Contained between double quotes "John". Literal character strings used for sentences or labels.
  • Number: Written without quotes 13.45 or 55. Can include integer or floating-point decimals.
  • Variable: No double quotes (e.g. first_name). Holds one value at a time; computer replaces it with held data during evaluation.

Variable Naming Directives

Hard Rules (Strict Computer Constraints):

  • Cannot start with a number (4square)
  • No spaces allowed (first name)

Soft Rules (Style & Clarity Best Practices):

  • Must mean something & be understandable (SET sum = 9 vs SET v = 1)
  • Avoid uncommon abbreviations (kg is fine; avoid thnks4thmmrs or osha)

4. Calculations, PEMDAS & Modulus Breakdown

PEMDAS Order of Operations

P :: () Parentheses
E :: ^ Exponents (2^3 = 8)
MD :: * / % (Mult, Div, Mod)
AS :: + - (Add, Sub)

Modulus Operator (%) Edge Cases

A % B divides A by B and returns the remainder.

5 % 2 = 1 (5 / 2 = 2, Remainder 1)

14 % 3 = 2 (14 / 3 = 4, Remainder 2)

3 % 14 = 3 (If left is smaller, result is left number!)

15 % 3 = 0 (Divides evenly, remainder is 0)

5. Output Annotations & Prompts

Enhancing program output so users aren't left confused by raw values.

Annotations & Trailing Spaces

Combining a String with a Number ("Your total is: " + 55) provides context. Always add a trailing space inside the quotes so numbers don't glue to the text!

# Without Space:

PRINT "Your total is:" + 55

Output: Your total is:55

# With Trailing Space:

PRINT "Your total is: " + 55

Output: Your total is: 55

Prompting Before INPUT

INPUT pauses execution silently. Always place a PRINT prompt directly above an INPUT so the user knows what to type!

PRINT "How tall are you in cm?"

INPUT height

6. 2-Step Problem Solving Workflow

How to convert human-language problem statements into structured pseudocode blueprints:

Step 1: Translate Verbs to Keywords

  • "ask/prompt user..." → INPUT
  • "calculate..." → SET
  • "display/show/tell..." → PRINT

Step 2: Assemble Skeleton & Syntax

Pair every INPUT with a preceding prompt PRINT. Split compound verbs like "Calculate and display" into distinct SET and PRINT steps!
